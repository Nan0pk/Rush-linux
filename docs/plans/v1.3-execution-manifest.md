A chunk is only complete when a verifier produces literal command transcripts per `docs/agent-protocol.md` and the affected docs are updated through `docs/docmap.toml`.

## Core read of the project

Rush Linux is already past the blank-project phase. The correct framing is:

> clean the truth surface → harden and package standalone `optid` → ship explainable drain/sleep insight → run privacy-safe LiveDev hardware evidence campaigns → promote safe opt-in domains by evidence → split planner/actuator boundaries → expand into the full Rush Linux desktop/OS experience.

Do not restart from the Grand Plan. Merge the Grand Plan into the live repo reality.

## Non-negotiable constraints

1. `docs/SPEC-northstar.md` remains canon: minimize avoidable platform energy subject to per-workload-class responsiveness floors.
2. `release/milestones.toml` remains the release/evidence source of truth.
3. `optid` remains the single runtime policy owner.
4. Agents may implement chunks, but may not verify their own work or alter release truth.
5. Any unshipped idea goes to `docs/research/` or an ADR, not to chat history or loose notes.
6. Unsafe/hardware-specific actuation stays behind the actuation rule: contract gate + safety gate + mutation gate + reversibility gate.

## Immediate critical path

### Phase 0 — Secret hygiene and repo preflight

**Goal:** prevent operational mistakes before more automation lands.

Chunks:

- **P0.1 Token hygiene note**
  - Human action: revoke any token pasted into chat or logs.
  - Agent action: no code change unless a token or secret is found in repo history.
  - Verification: `git grep -n "github_pat_\|ghp_\|GITHUB_TOKEN=" -- . ':!release/evidence/**'` returns no committed secret.

- **P0.2 Truth-surface audit**
  - Compare `VERSION`, `Cargo.toml`, `release/milestones.toml`, README release links, and GitHub latest release.
  - Output a small report under `release/evidence/dragnet/` or a dated reassessment snapshot.
  - Acceptance: contradictions are either fixed or explicitly listed with owner + target PR.

### Phase 1 — Public face cleanup

**Goal:** make the public repo stop contradicting itself before asking users for hardware trust.

Chunks:

- **P1.1 Version drift fix**
  - Paths: `VERSION`, `Cargo.toml`, `release/milestones.toml`, README release section.
  - Acceptance: one canonical current version; README testOS/latest-release line does not imply a different project version.

- **P1.2 Capability matrix generator**
  - Source: `release/milestones.toml`.
  - Output: generated Markdown table consumed by README or `docs/IMPLEMENTATION_STATUS.md`.
  - Acceptance: matrix is not hand-edited; CI fails if generated matrix differs.

- **P1.3 Evidence visibility page**
  - Path: improve or create `release/evidence/README.md` as the public evidence index.
  - Acceptance: casual visitor can see which milestones are complete, pending, or hardware-gated.

### Phase 2A — Standalone `optid` hardening and packaging

**Goal:** ship what already exists instead of rebuilding it.

Chunks:

- **P2A.1 Packaging matrix**
  - Targets: Arch first, then Fedora/Ubuntu packages or install scripts.
  - Acceptance: install/uninstall dry-run transcript for each target; package never enables mutating mode silently.

- **P2A.2 `optctl explain drain`**
  - Output measured facts and inferred causes separately.
  - Confidence labels: `HIGH` direct measurement, `MEDIUM` correlated inference, `LOW` heuristic.
  - Acceptance: `--show-work` prints raw counters used for each claim.

- **P2A.3 `optctl explain sleep`**
  - Inputs: wakeup sources, suspend statistics, recent device runtime PM state where available.
  - Acceptance: never blames an app/device as fact unless directly measured; otherwise marks inference.

- **P2A.4 Actuator refusal metrics**
  - Any refused planner/action request increments a counter and surfaces in `optctl status`.
  - Acceptance: silent refusal impossible in tests.

### Phase 2B — Opt-in domains and hardware evidence campaign

**Goal:** make the deeper power domains discoverable, testable, reversible, and promotable by evidence.

Chunks:

- **P2B.1 Domain opt-in UX**
  - Add per-domain enablement for storage, USB/runtime PM, dGPU, backlight/display.
  - Acceptance: unknown hardware defaults to safe baseline; risky toggles require explicit opt-in and show expected risk.

- **P2B.2 Snapshot schema and privacy audit**
  - Default snapshot excludes MACs, serials, raw logs, hostname, username, filesystem paths.
  - Verbose snapshot requires preview + explicit confirmation.
  - Acceptance: schema validator blocks forbidden fields.

- **P2B.3 Auto-promotion rule**
  - Rule: after N independent clean snapshots for a hardware class, domain setting graduates from opt-in to default-on for that class.
  - Suggested N: 5; human may override.
  - Acceptance: promotion creates a reviewable PR and never mutates allowlist truth directly.

- **P2B.4 Reference hardware closure**
  - Human fills desktop + laptop slots in `docs/strategy/reference-hardware.md`.
  - Acceptance: Phase D can run; v0.6 hardware-gated criteria no longer blocked by TBDs.

### Phase 3 — Planner / actuator boundary

**Goal:** reduce privilege and make refusal/revert semantics mechanically obvious.

Chunks:

- **P3.1 Boundary design ADR**
  - Decide separate process now vs staged internal trait boundary first.
  - Acceptance: pros/cons/risks recorded; no implementation before decision.

- **P3.2 IPC protocol draft**
  - Planner emits typed action requests; actuator returns applied/denied/error with reason.
  - Acceptance: denial and partial-apply behavior specified.

- **P3.3 Watchdog and revert semantics**
  - If planner dies, actuator returns to safe baseline or keeps last safe state by explicit policy.
  - Acceptance: failure modes covered in tests.

### Phase 4 — Full-stack modules

**Goal:** expand by independent modules, not by a monolithic rewrite.

Chunks:

- **P4.1 Sleep quality engine** — wakeup-source attribution, suspend blocker detection, S0ix preferred with S3 fallback.
- **P4.2 Power Intent Bridge v1** — GameMode + systemd/cgroup/scope signals now; portal/compositor work later.
- **P4.3 Thermal-acoustic comfort** — powercap/thermal budget; fan/noise policy only where interfaces exist.
- **P4.4 Display/render power** — backlight first; PSR/VRR/DPMS/render scaling as compositor-cooperation research.
- **P4.5 App-to-hardware telemetry** — local-first attribution, confidence-labeled, no per-PID energy overclaim.

### Phase 5 — Rush Linux desktop/OS experience

**Goal:** wrap proven optimizer behavior in an installable OS.

Chunks:

- **P5.1 Desktop target decision**
  - Recommendation: Mutter/GNOME first for mainstream desktop edition; wlroots first only for Power Intent Bridge plugin experimentation.

- **P5.2 Installer and rollback UX**
  - Preserve UKI/systemd-boot/signed rollback direction.
  - Acceptance: user can recover from bad update without expert shell work.

- **P5.3 User-facing UX minimum**
  - Show current class, energy/drain status, and one time-limited performance pin.
  - Do not expose sysfs-style knobs as normal UI.
